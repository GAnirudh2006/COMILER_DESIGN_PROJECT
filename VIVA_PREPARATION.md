## 1. Compiler Architecture & Design Decisions

### Q1: Why design a Domain-Specific Language (DSL) instead of just using Python with Biopython?
**Answer:**  
In general-purpose Python, biological sequences are stored as standard strings (`str`). The Python interpreter has no domain awareness of biology: it will happily allow a programmer to store `"AUGC"` into a variable intended for DNA, pass a protein string to `reverse_complement()`, or transcribe an RNA sequence. These errors only surface at runtime when a library throws a generic exception, or worse, they execute silently and produce invalid scientific results.  
**GenomeDSL** elevates `DNA`, `RNA`, and `Protein` to **first-class types enforced at compile-time**. Biological errors are flagged during semantic analysis before any execution begins, reducing errors and providing a compact, readable syntax.

### Q2: Why did you choose Lark as the parser generator?
**Answer:**  
Lark is a modern parsing library for Python that supports both **Earley** and **LALR(1)** algorithms. It allows defining grammars in clean EBNF notation with zero boilerplate. Crucially for a compiler, Lark supports `propagate_positions=True`, enabling AST nodes to retain precise source location metadata (line numbers and column numbers) for compiler diagnostics.

### Q3: Why represent the AST using Python dataclasses rather than nested dictionaries or tuples?
**Answer:**  
Python `dataclasses` (`Program`, `VarDecl`, `AssignStmt`, `FunctionCall`, `Literal`, `Identifier`) provide:
1. **Strong typing and readability:** Clear fields with type hints.
2. **Visitor/Pattern matching support:** Easy inspection via `isinstance()`.
3. **Decoupling:** Decouples the concrete parse tree generated by Lark from the abstract semantic representation needed by the semantic analyzer and optimizer.
4. **Diagnostic tooling:** Allows clean pretty-printing (`ast.pretty()`) of the tree structure.

## 2. Lexical & Syntactic Analysis

### Q4: Explain your grammar specification in `genomedsl/grammar.py`.
**Answer:**  
The grammar is specified in EBNF:
- **Statements:** Declarations (`TYPE_NAME CNAME "=" expr`), assignments (`CNAME "=" expr`), output (`PRINT expr ("," expr)*`), and visualization (`PLOT function_call`).
- **Expressions:** Function calls (`CNAME "(" [arg_list] ")"`), string/numeric literals, and variable identifiers.
- **Types:** Terminals for `DNA`, `RNA`, `Protein`, and `RESULT`.
- **Comments & Whitespace:** Handled via `%ignore WS_INLINE`, `%ignore COMMENT` (supporting `#` and `//`), and `%ignore ";"`.

### Q5: How does the parser handle line and column tracking?
**Answer:**  
When Lark parses tokens, it attaches `line` and `column` attributes. In `ASTBuilder(Transformer)`, each transformer rule extracts `getattr(token, "line", None)` and attaches it to the resulting AST dataclass instance. When an error occurs in subsequent compiler phases, the AST node provides the exact line and column to format an informative diagnostic pointer.

## 3. Symbol Table & Semantic Analysis

### Q6: How does the Symbol Table work in GenomeDSL?
**Answer:**  
The `SymbolTable` class (`genomedsl/symbol_table.py`) maintains a dictionary mapping variable names to `Symbol` objects containing:
- `name: str`
- `type_name: str` (`DNA`, `RNA`, `Protein`, `RESULT`)
- `line` and `column` of declaration
- Optional compile-time known constant value.

If a variable is declared twice in the same scope, the symbol table raises a `SemanticError` with reference to the previous declaration. If an undeclared identifier is referenced in an expression, lookup returns `None`, triggering an undeclared variable error.

### Q7: Explain the difference between `AlphabetError` and `BiologicalTypeError`.
**Answer:**  
- **`AlphabetError`:** Raised when the string literal characters violate the biological alphabet of the declared type. For example, `DNA x = "AUGC"` fails because `U` (Uracil) is not in $\{A, T, G, C\}$.
- **`BiologicalTypeError`:** Raised when an operation is applied to an incompatible biological sequence type. For example, `transcribe(rna_seq)` fails because transcription biologically operates only on DNA templates, producing RNA.

### Q8: What are the type compatibility rules for assignments?
**Answer:**  
In `visit_var_decl` and `visit_assign_stmt`:
- The RHS expression's inferred type must match the LHS declared type.
- `RESULT` is a generic analysis type that can hold numeric values (such as GC percentage), integer lengths, or coordinate lists from `find_motif`.
- Directly assigning an `RNA` expression (e.g. from `transcribe()`) to a `DNA` variable is rejected as a `BiologicalTypeError`.

## 4. AST Optimization

### Q9: What optimizations are implemented in GenomeDSL?
**Answer:**  
Two compiler optimizations are implemented in `genomedsl/optimizer.py`:
1. **Constant Expression Folding:** When an analysis function (such as `gc_content("ATGC")` or `transcribe("ATGC")`) receives static literals, the optimizer evaluates the result at compile-time and replaces the `FunctionCall` node with a `Literal` node (e.g. `Literal(FLOAT: 50.0)`).
2. **Reversible Operation Reduction:** Algebraic pattern matching that simplifies self-inverting biological operations:
   - $\text{reverse}(\text{reverse}(x)) \rightarrow x$
   - $\text{reverse\_complement}(\text{reverse\_complement}(x)) \rightarrow x$ (for nucleic acids).

### Q10: How does constant propagation work in the optimizer?
**Answer:**  
The optimizer maintains a `constant_env` dictionary. When a variable is initialized with a literal (e.g. `DNA gene = "ATGC"`), its value is recorded. Later statements that reference `gene` inside an optimizable function (e.g. `RESULT gc = gc_content(gene)`) resolve `gene` to `"ATGC"` and fold the expression into `50.0`.

## 5. Execution Backend & Visualization

### Q11: How does the backend execute an AST?
**Answer:**  
The `ExecutionBackend` (`genomedsl/backend.py`) walks through the optimized AST:
- Maintains an execution memory environment `env[var_name] = (value, type_name)`.
- Evaluates statements sequentially.
- For biological operations (`transcribe`, `translate`, `reverse_complement`), it delegates the core sequence manipulation to Biopython (`Bio.Seq.Seq` and `Bio.SeqUtils.gc_fraction`).
- For output, it formats values and logs them to `stdout`.
- For `PLOT`, it invokes `visualizer.py`.

### Q12: How does the visualization system work?
**Answer:**  
In `genomedsl/visualizer.py`, the `PLOT gc_content(seq)` statement computes a sliding-window GC percentage across coordinates with a dynamic window size (default 10bp). Using Matplotlib configured with the non-interactive `Agg` backend, it produces a dual-panel figure:
- Top panel: GC-content percentage curve with an average GC reference line.
- Bottom panel: Nucleotide frequency bar chart displaying counts of A, T, G, and C.
The figure is saved to `./evidence/gc_profile.png` without requiring a display server.

## 6. Student Implementation Zone (25% Contribution)

### Q13: What specific features were reserved for your implementation?
**Answer:**  
Four integrated features were reserved for independent implementation:
1. **Protein Alphabet Validation (`_validate_protein_alphabet` in `semantic_analyzer.py`):** Enforcing the 20 standard amino acid single-letter codes plus stop codon `*`.
2. **Sequence Similarity Metric (`_student_compare_sequences` in `backend.py`):** Computing percentage identity across sequences: $\frac{\text{matches}}{\max(\text{len}_1, \text{len}_2)} \times 100$.
3. **1-Based Motif Search with Overlaps (`_student_find_motif` in `backend.py`):** Detecting all 1-based start positions of a motif, correctly handling overlapping occurrences.
4. **Reversible Operation Reduction (`_simplify_reversible_calls` in `optimizer.py`):** Detecting nested inverse AST calls and simplifying them to the inner operand.

### Q14: How does 1-based coordinate indexing differ from Python standard indexing?
**Answer:**  
Python strings use 0-based indexing (`0, 1, 2, ...`). In biology, genome browsers and genetic sequence databases (such as GenBank, Ensembl, and FASTA files) universally use 1-based coordinates where the first nucleotide is at position 1. Therefore, when `find_motif()` identifies a match at Python index `pos`, it records `pos + 1`.

### Q15: Why is overlapping motif search important in bioinformatics?
**Answer:**  
In biological sequences, regulatory motifs (e.g. transcription factor binding sites, zinc fingers, or poly-A tracts) can overlap. For example, in the sequence `"AAAA"`, the motif `"AAA"` occurs twice: starting at position 1 (`AAA-`) and position 2 (`-AAA`). A naive search that jumps by the motif length would miss the second binding site. Advancing the search pointer by 1 (`sequence.find(motif, pos + 1)`) ensures biological accuracy.
